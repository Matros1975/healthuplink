Setup

Last updated 25 November 2026

Run the receiver on a machine that stays on, pair your iPhone with a QR code, then connect an agent. This is the short version; the README has every option.

With Tailscale (recommended)

Tailscale puts the server and the iPhone on one private network that WireGuard encrypts, so the receiver can use plain http:// and it works away from home too.

  1. Install Tailscale on the server and on the iPhone and log in to the same account. Note the server's address from tailscale ip -4 (it starts with 100.). The iPhone app cannot use *.ts.net names.
  2. Get the files and create the settings: 
    git clone https://github.com/Matros1975/healthuplink.git
cd healthuplink
cp .env.example .env
    In .env, with your own address and time zone: 
    HU_PUBLISH_ADDR=100.100.1.1
HU_PUBLIC_URL=http://100.100.1.1:8796
HU_TLS=off
HU_TZ=Europe/Berlin
  3. Start the receiver and print a pairing code: 
    docker compose up -d
docker compose exec healthuplink healthuplink pair
  4. In the iPhone app, tap Pair and scan the code. It works once and expires after 10 minutes.

On your home network with HTTPS

Without Tailscale, the receiver makes its own certificate and the QR code carries its fingerprint, so the phone talks only to this receiver. Use the server's LAN address (give it a fixed one in your router) or its .local name:

HU_PUBLISH_ADDR=192.168.1.10
HU_PUBLIC_URL=https://192.168.1.10:8796
HU_TLS=self-signed
HU_TZ=Europe/Berlin

Start and pair as above. When you pair, the app asks for Local Network access; allow it. A receiver behind an internet name such as health.example.com needs a certificate from a public certificate authority instead.

Without Docker

The receiver is also a Python package (Python 3.12 or newer):

pipx install healthuplink
export HU_PUBLIC_URL=http://100.100.1.1:8796
export HU_BIND=100.100.1.1:8796
export HU_TZ=Europe/Berlin
healthuplink serve

Pair from a second terminal with healthuplink pair. The README shows how to keep it running with a systemd --user unit.

Connect an agent

Create a token for each agent; it is printed once.

docker compose exec healthuplink healthuplink tokens create --name claude-code

Then add the receiver to Claude Code, with the same address as HU_PUBLIC_URL and /mcp at the end:

claude mcp add --transport http healthuplink http://100.100.1.1:8796/mcp \
  --header "Authorization: Bearer <token>"

Other MCP clients that support streamable HTTP with a bearer token work the same way. The tools are read-only; For AI agents lists them and explains the freshness data every answer carries.

More in the README, including how to trust a self-signed certificate.

Sync notices

The receiver can send you a message when uploads stop, through a webhook, ntfy or Telegram. A notice holds hours, counts and type names, never health values. See Sync notices in the README.

Something not working? Support lists the usual reasons sync stops.

Not a medical device. Health Uplink copies your Apple Health data to your server; it does not interpret it.
